## CP-004：消息动画分配失败链

**优先级：P1；职责：C 核心/ASS 输出；状态：待修。**

已有消息动画路径中，`getNewDlgListPtr`、COMBOLIST 等分配结果可能被立即解引用；`amendMessage`、`appendMessage`、`writeAliveMessage` 等多层 void 返回使上层无法可靠中止和报告失败。修复个别 NULL 判断不能自动解决部分结构已挂接后的释放与输出一致性。

**后续工作：**

1. 列出每种中间对象与链表节点的唯一所有者。
2. 将可能失败的函数改为返回状态或明确的可空结果，并传播到公开运行入口。
3. 新结构在全部必要分配成功后才提交到已有列表。
4. 任一步失败时释放本次未提交对象，已有对象保持可销毁。
5. 失败停止后续输出，返回与内存不足相符的错误。

**验收：**以定点分配失败注入覆盖每个分配点，检查无 NULL 解引用、无双释放、无泄漏、无半提交结构；任务返回错误且随后可安全销毁 context。失败注入测试是后续计划，本轮未运行。

## CP-005：数值边界不能停在单字段校验

**优先级：P1；职责：配置校验、排版、ASS；状态：部分修复。**

本轮已经收紧非有限值、整数解析、秒→毫秒与 ASS 结束时间组合检查，但仍有组合表达式：

- `textHei + line_spacing` 的 int 加法。
- 有效字号与内部 short 等窄类型转换。
- `getStrLen` 估算中的 int 乘法。
- 文本宽度与屏幕分辨率组合得到坐标的加法/乘法。
- 极大字号或分辨率使分配尺寸、循环边界和输出坐标超出表示范围。

**后续工作：**区分 API 输入范围、排版内部范围与 ASS 可表示范围；先用足够宽的整数做 checked 运算，再校验收窄；防止“单个字段都合法但组合溢出”。不要仅用 INT_MAX 作为所有字段的合理上限，也不要引入缺少文档依据的任意用户限制。

**验收：**大字号/大分辨率/正负行距、很长文本、极小显示区域及靠近时间上限的组合，分别得到正确结果或明确错误；不崩溃、不越界、不以回绕后的值排版。源码中的时间边界回归与几何回归不能代替尚未补的组合运算检查。

## CP-008：原生与 WASM 的正则差异

**优先级：P2；职责：C/WASM、JS、产品能力；状态：待处理。**

此前源码审查发现 WASM 分支省略 PCRE2 过滤路径。当前修正浏览器 loader 并未修复正则行为差异。相同配置在原生与 Web 可能输出不同过滤结果。

**可选方案：**

1. 为 WASM 建立与原生一致的正则实现，并以同一 fixtures 比较。
2. 若暂时不支持，能力查询和 UI 必须明确提示，拒绝依赖该功能的配置或要求用户显式接受降级。

不能静默忽略 blacklist-regex，也不能未经语义对照直接用 JS RegExp 替换 PCRE2 并声称完全兼容。

**原生失败路径补充（REV-066）：**文档回读时进一步确认 core/list.c 对正则编译失败、match data 分配失败和非正常匹配错误仍可能直接跳过，最终报告成功。无效规则应拒绝还是警告需要兼容策略；内存/匹配执行错误则应与正常 NOMATCH 区分并传播，避免部分过滤失效后输出被标记完整成功。此前 parallel realloc 修复没有覆盖这些路径。后续以无效规则、正常不匹配与定点分配/运行错误分别验收。

**验收：**相同输入、黑名单、大小写选项、Unicode 和边界表达式在两端相同；若不相同，行为差异在运行前可见且有固定测试。本轮未重建 WASM；当前 docs/wasm 旧二进制不能证明新 C 源码生效。

- 同格式转换、多个目录同名输入、Unicode/空格路径、已有输出、配置文件碰撞均要验收。
- 写出过程 fflush/fclose 延迟失败现在有源码处理，仍需实际故障验证。

**验收：**默认操作不破坏输入和已有输出；显式授权覆盖的行为清晰；磁盘满/写权限/关闭失败返回错误，不被记录为成功。

## CP-013：配置规范与单一事实来源

**优先级：P2；职责：架构；状态：建议。**

C parser、Rust CLI canonicalization、Slint 配置导入和 Web 参数构造均处理配置字段。现在多处独立维护 nested/flat aliases、默认值、case mode、blacklist 和坐标语义，容易在新增字段时漂移。

**下一步：**先固定配置规范与示例、默认值来源、类型/范围和覆盖语义，再决定共享 schema、生成映射或以 C effective config 导出为权威。不要只统一字段名而遗漏失败事务与运行时输入/输出字段。

**验收：**所有入口接受同一兼容 fixture；导入→修改→导出不丢未知保留字段或有明确策略；后文件和 CLI 覆盖规则一致。该建议并不代表必须立刻引入大型框架。

## CP-014：真实 ASS 预览

**优先级：P2 新功能；状态：讨论方案，未实现。**

共同管线：输入 + 当前配置 → C 生成 ASS → libass 按 timestamp 渲染 → RGBA → GUI 图像。字体测量模块仅帮助排版，GUI Text 模拟也不能准确复现 outline/shadow、ASS tags、运动、字体 fallback 与字形效果。

公开 API 当前没有 render_frame、内存 ASS 导出、preview session、实时进度回调或取消协议。第一版可以临时文件串联，之后再设计内存输出与缓存解析池。

**验收：**相同 ASS/timestamp/字体与背景，在独立 ASS 渲染结果和 GUI 预览中一致；参数改变去抖并后台处理；时间轴移动不重复解析全部输入；过期任务结果由 generation 丢弃。先静态背景，再按需求引入视频解码。

## CP-015：共享 Slint 原生与 Web

**优先级：P2 新功能；状态：最新讨论建议。**

共享 .slint UI、Rust 配置/状态和 C 源码；native DLL 与 Emscripten WASM 分开交付。薄 JS 桥承担字节、Worker 和下载，不另行重写全部业务界面。

**验收：**文件、字体、调度、存储、更新都通过平台服务；桌面路径不能直接传给浏览器；Rust 常规 fs/thread 与浏览器能力不能混用。原生仍需每个 OS/arch 构建测试；Web 单一构建覆盖多个系统不等于支持任意旧浏览器。

当前 docs HTML SPA 不等于共享 Slint Web 已完成。若实际旧浏览器测试失败，再评估保留简化 HTML 业务入口。

## CP-016：PWA 的完整版本与离线

**优先级：P2 新功能；状态：待实现。**

分别验收 manifest/安装、Service Worker 缓存、首次资源完整下载、离线转换、完整版本切换和失败恢复。更新等待转换结束，不能强制刷新正在运行的任务。

PWA 不负责原生 EXE/DLL 更新；浏览器关闭后实时后台更新不能保证；普通网页运行与可安装分别记录。[发布路线图](04-release-update-and-roadmap.md)保存具体生命周期。

## CP-017：Win7 与浏览器支持矩阵

**优先级：P2 产品契约；状态：历史调研目标，实际验证待办。**

此前没有承诺现代 Flutter/Slint 主原生程序支持 Win7。专用 Rust Win7 target 属于专项工程，不因改为软件渲染就自动解决全部系统 API、窗口、字体、对话框和运行库依赖。

候选兼容入口：Win7 + Firefox 115 ESR、Chrome 109 的 Web；不包含 IE11。支持政策来自 2026-10-01 调研，正式承诺前重新核实。以普通网页模式作为安装能力不足时的入口。不能把浏览器最低版本文档当作本项目已通过测试。

## CP-018：可靠更新与 ABI

**优先级：P2；状态：待实现。**

## 获准运行后的验证顺序

以下是计划，当前没有执行其中任何步骤。

### 第一层：公开接口和高风险回归

优先运行配置事务、JSON/XML 数据保持、ASS 读取/写入失败、排序、小区域/长文本/时间上限及绑定错误字符串等针对性检查。重点验证实际输出内容和错误，不只比较返回码。

新增 OOM/几何修复后，再执行故障注入与边界测试；若允许，使用合适的内存/未定义行为检测工具观察双释放、越界和泄漏。这些属于后续验证手段，不是当前已有通过记录。

### 第二层：CLI 契约矩阵

逐项覆盖旧参数名、短名、新别名、双值坐标、-c 零参数、多个文件覆盖、--save 独立路径、默认值导出、非交互覆盖、缺参数错误、Unicode/空格与 Unix 反斜杠路径。

### 第三层：构建、绑定与干净发行

覆盖 static/shared、宿主与交叉目标、Windows DLL、Linux/macOS rpath、Cargo target-dir、musl 架构和 test/example 输出目录。随后做没有开发缓存、没有预装可选运行库的离线包验收。

### 第四层：GUI 与浏览器行为

Slint 检查输入偏移未按 Enter 即点击转换、浮点字段精度、配置导入、碰撞输出、错误/取消/进度语义、键盘和窄屏布局。Web 检查胶水初始化、VFS 文件、字体 family、保存的格式、正则能力和 Worker。

旧浏览器、移动浏览器、原生不同平台分别记录，不能用 Node 测试代替。

### 第五层：新增预览、PWA 与更新

实现后才验收 timestamp 渲染、过期结果丢弃、缓存完整性、离线、跨标签页更新、网络中断、配置迁移、签名失败与回退。性能测量在功能和数据一致后进行，避免用更少功能的包获得虚假的优势。
